# DCNC-DAG: code and data

Code and experiment data for *Throughput-Optimal Control of Distributed
Computing Networks for Service DAGs*.

Version **0.1.1**. The release archive contains the simulator, input definitions,
recorded experiment data and reproduction scripts. Figures and summary tables
are generated from the recorded data; manuscript sources and PDFs are not
included.

## Contents

| Directory | Contents |
| --- | --- |
| `src/dcnc_sim/` | Network/DAG models, mapping algorithms, physical/virtual queues and scheduling |
| `scripts/` | Experiment runners, aggregation and plotting; FIFO/NTO code is in `scripts/fifo/` |
| `tools/` | Policy/frame sweeps and the optional DynVMP bridge |
| `inputs/` | Configurations, DAGs, topologies, full experiment matrix and plot settings |
| `data/runs/` | Results from 3,628 server runs, FIFO trajectories and unfinished MoE request arrivals |
| `data/table6.csv` | The 150 timing measurements used for Table 6 |
| `third_party/` | Required DynVMP dependency modules and their licenses |
| `tests/` | Regression checks for execution rules, request metrics, lower bounds and aggregation |
| `data/provenance/` | Original campaign protocol, observation source and per-record hashes |

## Install

Use Python 3.11 for the pinned reproduction environment. The package declares
Python 3.10 or newer; other interpreter versions may require different dependency
versions. Create and activate a virtual environment, then run from this directory:

```bash
python -m pip install -r requirements.txt -c constraints-main.txt
python -m pip install -e . --no-deps
```

The optional Python 2.7 DynVMP environment is separate and is not needed for
the commands in the next section.

## Reproduce figures and tables

```bash
python scripts/reproduce_paper_results.py
```

This aggregates the supplied data without running simulations. Output is
written to `results/exports/`, `results/tables/` and `results/figures/`.
Use `--output PATH` to change the destination, or `--skip-figures` for numbers
only. PNG figures and derived tables are generated on demand.

To aggregate a newly executed campaign with the same metric definitions:

```bash
python scripts/reproduce_paper_results.py --runs-dir results/campaign/results/runs --jobs-file results/campaign/jobs.json --output results/recomputed_campaign
```

`--runs-dir` selects input records; `--output` selects generated files. Use
`--summaries-only` with a partial jobs manifest to export runs and summaries
without manuscript tables/figures. FIFO aggregation requires both experiments
A and B. Raw records are never rewritten.

Table 6 timing is a separate input, not generated by a campaign. Default archive
reproduction uses `data/table6.csv`. With another `--runs-dir`, timing is omitted
unless `--timing-csv PATH` is explicitly supplied. `--skip-timing` also omits it
for archived runs. `aggregation_inputs.json` records the selected inputs.

Supported rates for Table 6 are in `results/tables/supported_rates.csv`, with
`campaign=frames`; `results/tables/table6.csv` contains timing summaries.
At F=256, the request-level supported rates are 0.784 (Milan) and 0.48 (Random),
displayed as 0.78 and 0.48 in the manuscript. Performance/frame runs use
`exact_dp`; the 150 archived timing measurements use `dynvmp_bridge`.

Request completion requires all sink outputs. All 12 delay panels use the
same **finite-horizon request-delay lower bound**. For one run with horizon T,

```
LB = (sum of completed-request delays + sum of unfinished-request ages) / arrivals
completed delay = completion-slot index - arrival-slot index
unfinished age  = T - arrival-slot index
```

The denominator includes every arrived request. The two numerator sums are
stored in each physical run's `audit.completed_request_delay_sum` and
`audit.pending_registered_request_age_sum`. All archived requests are registered;
there are no asynchronous buffered requests or injected control waits to add.
`scripts/delay_lower_bound.py` validates these conditions and produces
`results/exports/delay_lower_bound/{runs,summary}.csv` for all 3,248 physical runs.
Completed-only delays remain explicitly named in the other exports; they are
not relabeled as lower bounds.

This is a lower bound on the eventual mean delay of the recorded arrivals.
It is neither steady-state mean delay nor a lower bound on an optimal policy.
Comparisons of these bounds do not by themselves order eventual mean delays.
Values are first computed per seed and then averaged with equal seed weights;
all delay panels shade plus/minus one standard error across three seeds.
FIFO/NTO backlog bands retain 95% confidence intervals.

| Experiment | Horizon (slots) | Seeds |
| --- | ---: | --- |
| Main-policy comparison | 20,000 | 1, 2, 3 |
| Frame-length comparison | 100,000 | 1, 2, 3 |
| Workflows | 50,000 | 0, 1, 2 |
| MoE curves and Table 5 supported rates | 100,000 | 0, 1, 2 |

Supported rates use the full-grid mean of
`completed_service_units / total_service_units` at least 95%. MoE Table 5 now
uses the same 100,000-slot campaign as its curves. The 50,000-slot MoE records
and exports remain available, but do not supply this table. Consequently, the
Mixtral rates (DCNC-DAG-H, Lazarus-inspired, FlexMoE-inspired) are
(1.16, 0.38, 0.44), with gain 2.64; the Llama rates are (1.02, 0.30, 0.38),
with gain 2.68. Table 6 timing and its separate 150 input measurements are
unchanged. No simulations are run during archived reproduction.

All main/frame/workflow entry paths share `paper_metrics.py` and
`paper_aggregation.py`. Direct/native runner results carry
`request_metrics_schema=complete-request-v1`, request counts and explicitly
named `request_*` metrics. Result fields `avg_delay_completed`,
`avg_delay_with_penalty` and `completion_ratio` are request-level compatibility
aliases; workflow `*_jobs`, `job_throughput` and `job_completion_ratio` also
refer to complete requests. `sink_output_*`, `delivered_packets` and
`pending_packets` describe individual sink outputs.

Records without `request_metrics_schema` must supply request-level `stats`.
Aggregation requires complete-request metrics for these experiments.
Zero arrivals produce an undefined ratio; zero completions produce an undefined
completed delay (JSON null / CSV blank). A group with an undefined seed metric
keeps that aggregate undefined. Means and SEM otherwise use equally weighted
seed metrics, not pooled request counts. Lower bounds use the audit sums above:
zero completions can still give a defined bound; zero arrivals give an undefined
bound. Capacity statistics and FIFO backlog retain their own definitions.
Full lower-bound aggregation requires the observed campaign runner; `--native`
validation records without audit sums are rejected explicitly.

Resuming `paper_sweep.py` requires a matching metric schema. Campaign resume
requires matching code, inputs and runtime; otherwise use a separate
`DCNC_CAMPAIGN` directory.

The reproduction command generates 12 standalone delay PNGs, two overview
PNGs and the FIFO/NTO backlog PNG. Delay filenames end in
`_delay_lower_bound.png`; frame length is written **F**. Rendering uses fresh
data even if output PNGs already exist. Fonts use Times New Roman when
available, otherwise DejaVu Serif; image bytes may differ across environments.

Display selection is defined in `inputs/plots/policy_map.json`. Sort each
main-scenario curve by arrival rate and omit this many largest-rate points:

| Scenario | DCNC-DAG | DCNC-DAG-H | CTS | Randomized |
| --- | ---: | ---: | ---: | ---: |
| Driving / Milan | 1 | 4 | 4 | 3 |
| Driving / Random | 4 | 3 | 4 | 0 |
| Random DAG / Milan | 0 | 0 | 1 | 2 |
| Random DAG / Random | 1 | 1 | 5 | 3 |
| Random DAG / RoofNet | 4 | 5 | 6 | 0 |
| Random DAG / FlockLab | 4 | 6 | 4 | 0 |

MoE, workflow and frame curves use all their recorded rates. There are no
additional completion-ratio/delay filters, grid matching, or individual-point
exclusions. In particular, FlockLab H at 3.12 and Llama H at 1.05 are included;
Random/Random H retains 0.6957 and omits only the final point at 0.7593.

These are display choices, not stability tests. All 883 candidate points remain
in `results/figures/all_points.csv`; 818 displayed points are in `points.csv`;
65 omitted points are in `omitted_tail_points.csv`. `tail_trim_selection.json`
records the actual omitted rates and final displayed endpoints. The raw data
and support-rate estimates use the full grids. Disclose these display choices
when reporting the figures; curve endpoints are not supported-rate estimates.

## Check the installation

```bash
python -m unittest discover -s tests -v
python scripts/validate_new_7_2_capacity_lp.py --output-dir results/capacity_lp
```

The regression checks cover nonpreemptive service, next-slot eligibility,
activation ties, CTS placement, full-request completion, lower-bound arithmetic,
missing/undefined metrics, equal seed weights, display selection and identical
archive/campaign aggregation. They use small fixtures and bundled records;
they do not rerun the experiment matrix.

## Run simulations on a server

```bash
python scripts/run_campaign.py --workers 96
```

Run on a Linux server; adjust `--workers` to its resources. The full matrix is
`inputs/experiments.json`. New runs go to `results/campaign/`, or to the directory
specified by `DCNC_CAMPAIGN`. Completed runs can be resumed. The simulator uses
nonpreemptive service, next-slot successor eligibility, lexicographic virtual
max-weight activation and CTS placement based on placed direct predecessors.

The optional `dynvmp_bridge` solver uses Python 2.7 and separately licensed
Gurobi. Its environment is specified in `environment_dynvmp_py2.yml`; set
`DYNVMP_PYTHON` and `GRB_LICENSE_FILE` before using `tools/run_dynvmp_bridge.sh`.
The standard `exact_dp` solver and figure/table reproduction do not need it.
The Conda file records the Linux Python 2.7 environment used for that optional
path; it is not a portable Windows environment specification.

## Rebuild input instances

Run `python tools/rebuild_inputs.py --check` to regenerate and verify the
RoofNet-inspired topology and both workflow DAGs. Source snapshots, construction
recipes and parameter correspondence tables are in `inputs/construction/`.
Its short README also documents the explicit SIPHT graph adaptations and the
separate optional measurement-normalization tool.

## Topology counts

The supplied FlockLab graph contains 26 nodes and 338 directed arcs, forming
171 distinct unordered node pairs: 167 bidirectional pairs and four
unidirectional connections. Its dynamic subset contains 132 directed arcs
over 66 node pairs. The simulation uses the arcs listed in
`inputs/topologies/FlockLab_cap210_access.json`.
