# MoE evidence audit

Audit date: 2026-09-27.

The latest paper PDF reports FlexMoE-style thresholds of 0.52 for Mixtral and
0.44 for Llama, producing gains of 2.23 and 2.32. Neither value is supported by
the located experiment records.

The legacy Milan campaign reports, in the order DCNC-DAG-H, Lazarus-style,
FlexMoE-style, and gain:

- Mixtral: 1.10, 0.21, 0.40, 2.75;
- Llama: 1.00, 0.17, 0.36, 2.78.

The later canonical Milan-v2 campaign contains 252 raw rows per model: three
policies, 28 arrival rates, seeds 0/1/2, and a 50,000-slot horizon. Recomputing
the 0.95 seed-mean completion gate directly from those raw rows gives:

- Mixtral: 1.16, 0.35, 0.46, 2.52;
- Llama: 1.02, 0.28, 0.38, 2.68.

The paper's FlexMoE-style values 0.52 and 0.44 are not even points in the
corresponding canonical arrival-rate grids. Local copies of the canonical raw,
summary, and configuration files have the same SHA-256 values as the copies in
the active simulation project on `paper-server`. A read-only server search
found exactly two MoE threshold files across that project: the legacy Milan
file and the Milan-v2 file. Their remote SHA-256 values are, respectively,
`c6e50222aa1ab4209c13e99bccea11fbf23a67b35c8538c86fa30ff8e7c99c68`
and `ee257a7a1cffc5ac1c76db25b8bec04aabf5a78c5ea5a73309fae49bb820c71e`,
matching the audited records. Other located AI-benchmark and skewed-MoE
summaries use incompatible macro-rate protocols rather than the sub-unit
Milan-v2 table protocol. No third threshold file supports the paper values.
This server-wide revalidation was performed read-only on the active simulation
server at `2026-09-27T19:26:30+08:00`.

The alternative threshold conventions that might otherwise explain an
off-grid value were also checked. Appendix D.2 of the pinned PDF states that
all tabulated thresholds use the common 0.95 completion gate. Linear
interpolation of the three-seed mean FlexMoE curves at that gate gives
0.460361 for Mixtral and 0.393173 for Llama, not 0.52 and 0.44. Conversely,
linear interpolation at the paper's reported rates gives completion ratios of
only 0.912371 and 0.914455. Per-seed 0.95 thresholds are 0.44/0.46/0.44 for
Mixtral and 0.38/0.38/0.38 for Llama, so selecting a seed, median, minimum, or
maximum also cannot produce the paper values.

The parent paper Git history now identifies the exact manuscript source that
introduced the printed values. Commit
`defdbafd17aae3a10fa1d71f398eb879dee2ac42` added
`TMC (2)-integrated.tex`; its table `tab:sim_largedag_thresholds` contains the
same 0.52/0.44 and 2.23/2.32 entries as the pinned PDF. The commit updated the
two MoE plot PDFs but added or modified no raw, summary, or threshold CSV.
Moreover, the companion `TMC (2).tex` in the same commit still used the older
10.0/6.0 and 9.0/7.0 scale. This establishes the textual lineage of the claims
but does not supply experimental provenance for them.

Treating completed throughput as the intended metric does not recover the
table either. Across the FlexMoE raw grid, the maximum three-seed mean
completed throughput is 0.655227 for Mixtral and 0.572180 for Llama. Linear
interpolation of completed throughput at the paper's off-grid 0.52 and 0.44
rates gives only 0.476783 and 0.402761, respectively. These checks are now
recomputed from the raw CSVs by `scripts/verify_claims.py`.

The safe resolution is therefore either to correct the paper table to the
canonical raw-data values or to run and archive a valid replacement campaign.
The artifact must not treat the current PDF values as reproduced.

Machine-readable hashes, counts, claims, search scope, and conclusions are in
`audit.json`. `scripts/verify_claims.py` independently recomputes the canonical
thresholds, interpolation checks, and per-seed alternatives from the raw CSV
files and verifies the audit hashes.

`docs/MOE_RESOLUTION.md` records the exact manuscript corrections and the
minimum replacement-campaign evidence required to close this release gate.
